# Интеграция с Яндексом

В проекте четыре независимые интеграции. Каждую можно включить отдельно во
вкладке **Настройки** приложения.

| Что | Зачем | Что нужно |
|---|---|---|
| Яндекс.Календарь (CalDAV) | встречи и задачи в календаре Яндекса и обратно | аккаунт Яндекс 360 и пароль приложения |
| Yandex SpeechKit | распознавание и озвучка в облаке | API-ключ и Folder ID Yandex Cloud |
| YandexGPT | разбор свободных фраз, которые не поняли правила | тот же API-ключ Yandex Cloud |
| Навык Алисы | «Алиса, что у меня завтра?» и создание записей голосом | сервер с HTTPS и регистрация навыка |

Все ключи хранятся только на устройстве (SharedPreferences) и передаются
напрямую в API Яндекса. Сервер навыка Алисы хранит записи в JSON-файле.

---

## 1. Яндекс.Календарь

Приложение синхронизируется по протоколу CalDAV с календарём Яндекса.

### Подготовка

1. Войдите в [id.yandex.ru](https://id.yandex.ru) → **Безопасность** →
   **Пароли приложений** → создайте пароль для **Календаря**.
2. В приложении: **Настройки → Яндекс.Календарь**.
3. Включите переключатель, укажите логин (почту) и пароль приложения.
4. Нажмите **Синхронизировать**.

Пароль приложения — не основной пароль аккаунта. Основной пароль не подойдёт
и не должен вводиться в приложение.

### Что синхронизируется

- Задачи, встречи и напоминания с датой (в том числе «на весь день»).
- Название, время, длительность, место и комментарий.
- Отметка «выполнено» хранится в расширении `X-VOICE-ASSISTANT-DONE`.

Правила конфликтов: сравнивается время последнего изменения
(`LAST-MODIFIED` / `updatedAt`). Побеждает более свежая версия; при равенстве —
запись на устройстве. Синхронизируются события за 30 дней назад и 365 вперёд.

Повторная синхронизация не создаёт дубликаты: события связываются по `UID`,
который сохраняется в `externalId` записи.

### Если не подключается

| Симптом | Причина |
|---|---|
| «неверный логин или пароль приложения» | используется основной пароль вместо пароля приложения |
| «В аккаунте не найден календарь» | в аккаунте нет ни одного календаря или CalDAV отключён |
| пустой список событий | события вне диапазона −30…+365 дней |

Адрес календаря можно указать вручную (поле «Адрес календаря»), если
автоопределение через `PROPFIND` не сработало.

## 2. Yandex SpeechKit

Заменяет системные распознавание и синтез речи на облачные.

### Подготовка

1. Создайте каталог (folder) в [Yandex Cloud](https://console.yandex.cloud).
2. Создайте сервисный аккаунт и назначьте роли:
   - `ai.speechkit-stt.user` — распознавание;
   - `ai.speechkit-tts.user` — синтез;
   - `ai.languageModels.user` — для YandexGPT.
3. Создайте **API-ключ** сервисного аккаунта.
4. В приложении: **Настройки → Yandex SpeechKit и YandexGPT** → включите
   «Распознавать и озвучивать через SpeechKit».
5. Вставьте API-ключ и Folder ID, выберите голос и нажмите
   **Проверить голос**.

### Как работает

- Микрофон пишет PCM16 16 кГц в временный файл (`record`), затем файл
  отправляется в `stt:recognize`.
- Ответ озвучивается MP3 из `tts:synthesize` (`audioplayers`).
- Если ключ не задан, сеть недоступна или сервис вернул ошибку, приложение
  автоматически возвращается к системным движкам (`speech_to_text`,
  `flutter_tts`).
- В браузере облачное распознавание отключено (запись в файл недоступна),
  озвучка работает.

Голоса синтеза: `alena`, `filipp`, `jane`, `omazh`, `zahar`, `ermil`.
Пустой выбор означает «алёна» для женского голоса и «филипп» для мужского.

Тарификация: SpeechKit платный, но новым аккаунтам обычно доступен пробный
грант. Следите за квотами в консоли.

## 3. YandexGPT

Правила разбора остаются основными: они работают офлайн, мгновенно и
бесплатно. YandexGPT вызывается только если правила вернули «не понял».

### Подготовка

1. Используйте тот же API-ключ и Folder ID, что и для SpeechKit.
2. Включите **«Понимать свободные фразы через YandexGPT»**.
3. Выберите модель: `yandexgpt-lite` (быстрее и дешевле), `yandexgpt`,
   `yandexgpt-32k`.

Модель получает системную инструкцию и текущую дату, возвращает JSON с
намерением, типом записи, названием, датой и временем. Ответ проверяется:
если JSON некорректен или намерение `unknown`, используется обычный ответ
ассистента.

## 4. Навык Алисы

Алиса не может обратиться к приложению на телефоне напрямую, поэтому нужен
небольшой сервер: он принимает вебхук Яндекс.Диалогов и синхронизирует
записи с приложением.

Сервер лежит в `packages/alice_server`, общая логика ассистента — в
`packages/assistant_core` (те же модели, NLU и диалог, что в приложении).

### Запуск локально

```bash
cd packages/alice_server
dart pub get
dart run bin/server.dart --port 8080 --data data/store.json
```

Проверка: `http://localhost:8080/health` → `{"ok":true}`.

### Публикация на сервере

Нужен HTTPS-адрес: Яндекс.Диалоги не принимают `http://`.

Вариант с Caddy (сам получает сертификат):

```
alice.example.ru {
    reverse_proxy 127.0.0.1:8080
}
```

Запуск как службы (systemd):

```ini
[Unit]
Description=Alice skill server
After=network.target

[Service]
WorkingDirectory=/opt/voice_assistant/packages/alice_server
ExecStart=/usr/bin/dart run bin/server.dart --port 8080 --data /var/lib/alice/store.json
Restart=always
User=alice

[Install]
WantedBy=multi-user.target
```

Для облачных платформ достаточно передать `PORT` и `DATA_FILE` через
переменные окружения. Файл данных должен лежать на постоянном диске.

### Регистрация навыка

1. Откройте [dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer)
   → **Создать навык** → **Навык в Алисе**.
2. Название: например, «Мой ассистент».
3. Активационное имя — то, что вы скажете Алисе.
4. **Backend**: `https://alice.example.ru/alice`.
5. Тип доступа: публичный или «только для меня».
6. Сохраните и протестируйте во вкладке **Тестирование**.

### Привязка аккаунта

1. В приложении: **Настройки → Алиса** → укажите адрес сервера
   (`https://alice.example.ru`) и включите синхронизацию.
2. Нажмите **Создать аккаунт** — сервер выдаст токен, он сохранится в
   настройках.
3. Нажмите **Код для Алисы** — приложение покажет шестизначный код
   (действует 15 минут).
4. Скажите Алисе: **«Свяжи аккаунт, код 123456»**.
5. Нажмите **Синхронизировать** — записи приложения появятся у Алисы.

Примеры фраз:

- «Алиса, спроси у моего ассистента, что у меня завтра».
- «Напомни завтра в 10 утра позвонить Ивану».
- «Отметь задачу про отчёт выполненной».
- «Отвяжи аккаунт».

### REST API сервера

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/alice` | вебхук Яндекс.Диалогов |
| POST | `/api/register` | новый аккаунт: `{name}` → `{userId, token}` |
| POST | `/api/pair` | код привязки (Bearer) |
| POST | `/api/sync` | обмен записями (Bearer) |
| GET | `/api/entries` | все записи (Bearer) |
| POST | `/api/unlink` | отвязать Алису (Bearer) |
| GET | `/health` | проверка сервера |

Авторизация приложения — `Authorization: Bearer <token>`. Токен выдаётся при
регистрации и хранится только на устройстве.

Слияние записей: клиент присылает свои записи, сервер сравнивает по
`externalId` и `updatedAt`, возвращает полный список. Новые записи получают
`externalId = cloud:<id>`, поэтому повторная синхронизация не создаёт
дубликаты.

### Когда происходит обмен

Приложение обменивается записями с сервером при запуске, затем каждые
15 минут и по кнопке «Синхронизировать» в настройках. Фоновый обмен не
задерживает старт и не накладывается сам на себя: если предыдущая синхронизация
ещё идёт, новая пропускается.

### Ограничения

- Один процесс сервера и JSON-файл: для семьи или демо достаточно, для
  большого числа пользователей нужна настоящая БД.
- Нет OAuth-привязки: используется код из приложения (проще и без
  регистрации приложения в Яндексе).
- Если сервер недоступен, приложение продолжает работать локально; записи
  синхронизируются при следующем запуске или на следующем цикле каждые
  15 минут.

## Проверка

```bash
# приложение
flutter analyze
flutter test

# сервер навыка
cd packages/alice_server
dart analyze
dart test
```

Тесты покрывают разбор iCalendar, маппинг записей, разбор JSON YandexGPT,
отключение облачных сервисов без ключей, слияние записей при синхронизации
и полный сценарий «привязка → создание записи голосом → список».
